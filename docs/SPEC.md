# AC Livery — техническое задание

Рабочее название: **AC Livery**. Десктопная программа для создания ливрей (скинов) для Assetto Corsa: редактор винилов в духе Forza/GT7, универсальные шаблоны, которые ложатся на любую машину, и массовая генерация скинов для лиги.

Статус документа: черновик по итогам опроса. Раздел «Решения по умолчанию» — это то, что я выбрал сам. Любой пункт можно оспорить.

## 2. Как это работает (ключевая идея)

### 2.1. Пространство машины

Каждый винил — это **проектор**: ортогональная «коробка» с позицией, поворотом, размером и глубиной, заданная в координатах машины. Координаты нормализуются по габаритам кузова (без колёс), поэтому один и тот же дизайн встаёт в ту же относительную точку и на Miata, и на GT3.

- Позиция задаётся в долях габаритов кузова (длина / высота / ширина).
- Размер задаётся относительно длины кузова, пропорции сохраняются.
- Флаг «зеркалить на другой борт» создаёт отражение проектора по оси X.

### 2.2. Запекание в текстуру

Для каждой перекрашиваемой текстуры машины:

1. Меши, использующие эту текстуру, рендерятся **в UV-пространстве**: позиция вершины = её UV, в шейдер передаются мировая позиция и нормаль.
2. Фрагментный шейдер проходит по слоям винилов: проецирует точку в пространство проектора, отбрасывает поверхности, повёрнутые к проектору под слишком большим углом (иначе будут растяжки), сэмплирует растеризованный винил и смешивает слои.
3. Параллельно по «финишу» каждого винила (мат / глянец / металлик / хром) пишется карта материалов `txMaps`.
4. Поверх результата multiply накладывается слой AO и деталей из стокового скина.
5. Дилатация (расширение краёв UV-островов), чтобы не было швов на стыках.
6. Кодирование в DDS.

2D-виды — это тот же 3D-рендер с ортогональной камерой. Поэтому редактирование на них и в 3D работает с одними и теми же проекторами.

### 2.3. Какие текстуры перекрашиваются

Автоопределение: берём текстуры, которые переопределяются в папках `skins/*` этой машины. Главная текстура кузова — та, которая покрывает наибольшую площадь поверхности кузова. Диски, суппорты и стёкла определяются по именам мешей и материалов (`RIM`, `CALIPER`, `GLASS`, `WINDSCREEN` и т. п.). Для каждой машины есть **профиль**, где всё это можно поправить вручную. Профиль сохраняется и переиспользуется.

### 2.4. AO и детали из стокового скина

Из стоковых скинов машины автоматически выбирается «самый чистый»: светлый и наименее насыщенный, обычно белый. Из него извлекается карта затенения: яркость, нормированная на локальный базовый цвет, с ограничением «только затемнение». Пользователь может выбрать другой скин-источник, изменить силу эффекта или выключить его.

## 3. Архитектура

```
Electron
├── main (Node)
│   ├── поиск AC: реестр Steam + libraryfolders.vdf, ручной путь
│   ├── ФС: машины, скины, запись результата
│   ├── texconv.exe (DirectXTex, MIT): кодирование DDS
│   └── IPC-API для renderer
├── shared (чистый TS, тестируется в Node)
│   ├── форматы: kn5, DDS (чтение), ini, ui_skin.json, CSV/XLSX
│   └── модель проекта: zod-схемы, миграции версий
└── renderer (React)
    ├── UI: слои, свойства, галерея шаблонов, таблица пилотов
    ├── engine/viewer: Three.js, эмуляция шейдеров AC
    ├── engine/baker: запекание проекций в UV (WebGL2)
    └── engine/vinyl: растеризация фигур, текста (opentype.js), SVG, PNG
```

- Сборка: `electron-vite`. Упаковка: `electron-builder` (NSIS-инсталлятор и portable). Автообновление через GitHub Releases.
- Состояние: Zustand + immer, undo/redo на патчах immer.
- i18n: i18next (RU по умолчанию, EN).
- Тесты: Vitest для `shared` и движка, Playwright для e2e Electron.
- CI: GitHub Actions на `windows-latest`: линт, тесты, сборка; релиз по тегу.
- Качество кода: TypeScript strict, ESLint, Prettier.

### 3.1. Модель данных (упрощённо)

```ts
Project {
  version
  car?: CarRef                 // для проекта под конкретную машину; у шаблона пусто
  params: Param[]              // переменные: цвета, тексты, слоты картинок
  targets: {
    body:     { base: Paint; layers: Layer[] }  // проекционные винилы
    rims?:    { paint: Paint }
    calipers?:{ paint: Paint }
    glass?:   { tint; layers: Layer[] }         // баннер на лобовом — тоже проекция
  }
  csp?: CspPaintSettings       // флейки, перламутр, хамелеон...
  meta: UiSkinMeta             // skinname, drivername, team, number, country
}

Layer = Group | Vinyl
Vinyl {
  kind: shape | text | image | flag
  projector: { pos; rot; size; depth; mirror }  // в нормализованных координатах машины
  fill: Paint | ParamRef       // цвет можно привязать к переменной
  finish: gloss | matte | satin | metallic | chrome
  opacity; blend; locked; hidden
}
```

**Шаблон** — это тот же проект, в котором часть свойств привязана к параметрам (`{number}`, `{driver}`, `color.primary`, `sponsor.1`...). Генератор заполняет параметры через форму, лига — строками таблицы. Один механизм на все три сценария.

Файл проекта / шаблона: `.aclivery` — ZIP с `project.json` и ассетами (картинки, шрифты).

## 4. Этапы

### Этап 0. Каркас

electron-vite + React + TS, линт, тесты, CI, i18n, лицензия GPL-3.0, README.

### Этап 1. Ядро: от машины до скина в игре

- Поиск папки AC, список машин и их скинов.
- Парсер `.kn5`: текстуры, материалы, дерево нод, меши; распознавание зашифрованных файлов.
- Чтение DDS (DXT1/3/5, BC7 через texconv).
- 3D-вьюер с эмуляцией `ksPerPixel`, `ksPerPixelMultiMap` (`txMaps`), `ksPerPixelNM`, fresnel; скины из папки поверх текстур kn5.
- Автоопределение перекрашиваемых текстур и профиль машины.
- Сквозной сценарий: **залить кузов одним цветом + AO из стока → записать скин в игру** (DDS, `ui_skin.json`, `preview.jpg`, `livery.png`).

**Статус: готово, проверено на Porsche 919 Hybrid 2016.** По итогам проверки добавлено:

- выбор текстуры ливреи по доле видимой поверхности (ID-рендер с 7 ракурсов), а не по площади мешей;
- ручной выбор перекрашиваемых текстур (можно несколько) и базового скина для остальных текстур, которые копируются в новый скин;
- отрисовка стоковых наклеек-мешей (альфа-тест `*_AT`, режимы глубины, смещение глубины для наклеек);
- диагностика на вкладке «Модель»: клик по детали, скрытые меши, отчёт для разработчика.

### Этап 2. Редактор винилов

- Фигуры (прямоугольник, круг, полигон, полоса, звезда, стрелка...), текст с TTF/OTF, SVG, PNG/JPG.
- Слои, группы, порядок, блокировка, видимость, прозрачность.
- Размещение в 3D (raycast, проекция по направлению взгляда) и на 2D-видах, гизмо трансформации, привязки и выравнивание, зеркалирование.
- Финиши (мат / глянец / металлик / хром) → `txMaps`.
- Undo/redo, автосохранение, сохранение и открытие `.aclivery`.

**Статус: готово.** Первая итерация проверена на Porsche 919 Hybrid 2016 (по итогам исправлены detail-текстура краски, альфа-тест наклеек и запекание мешей с UV вне 0..1: у моделей Kunos кузов лежит в диапазоне v −1..0).

Сделано:

- 9 фигур, текст (системные шрифты и свои TTF/OTF/WOFF, жирный, курсив, обводка), картинки PNG/JPG/WebP/SVG;
- слои: порядок, видимость, блокировка, прозрачность, копия, удаление;
- группы: выделение нескольких слоёв (Ctrl/Shift+клик в списке, Ctrl+клик на машине, Ctrl+A), Ctrl+G / Ctrl+Shift+G, клик по машине выбирает всю группу, группа двигается, масштабируется и вращается целиком, переносится в стеке как один слой;
- проекторы в координатах машины (позиция в долях габаритов, размер в долях длины), запекание в UV на GPU с отсечением поверхностей, повёрнутых от проектора, и ограничением по глубине, поэтому наклейка не протекает на другой борт;
- размещение в центр текущего вида (3D или 2D), перетаскивание мышью по машине, ручки на машине (уголки — размер, кружок — поворот, Shift — шаг 15°, притяжение к 0/90/180/270°), Shift+колесо — размер, Alt+колесо — поворот, стрелки — сдвиг, ползунки размера, поворота, глубины;
- привязка к оси машины при перетаскивании на крыше, капоте, носу и корме (Alt отключает), кнопки «На ось машины» и «По центру длины», выравнивание выделения по краям и центрам;
- зеркалирование на другой борт: читаемая копия или зеркальная;
- финиши основы и каждого винила (как в стоке / глянец / сатин / мат / металлик): запекаются в карту материалов `txMaps` той же развёртки (R — блик, G — глянцевость, B — отражения) и записываются в скин;
- undo/redo (Ctrl+Z / Ctrl+Y), Delete, Ctrl+D;
- файл проекта `.aclivery` (ZIP: `project.json` + картинки и шрифты файлами): Ctrl+S / Ctrl+Shift+S / Ctrl+O, при открытии программа переключается на машину проекта, если она установлена, иначе дизайн ложится на текущую; main-процесс пишет проекты только туда, куда пользователь указал в диалоге;
- автосохранение несохранённой работы и предложение восстановить её при следующем запуске;
- дизайн также сохраняется в маркере скина и открывается кнопкой «Редактировать»;
- «Убрать из скина»: стоковые наклейки, номера и имена заменяются прозрачной текстурой.

Отложено: визуальные направляющие при привязке, распределение слоёв с равным шагом, вложенные группы.

### Этап 3. Диски, суппорты, стёкла, CSP

- Перекраска дисков и суппортов (тонирование стоковой текстуры по маске).
- Тонировка стёкол, баннер на лобовом.
- Эффекты CSP в `ext_config.ini` скина: флейки, перламутр, хамелеон, хром. Точный формат сверим с актуальной документацией CSP.

**Статус: готово, ждёт проверки в игре.** Новая вкладка ливреи «Детали»:

- текстуры дисков, суппортов и стёкол находятся по категориям мешей (имена мешей и материалов, узлы `WHEEL_*`); общие атласы, листы наклеек, detail-текстуры и стёкла повреждений не трогаются;
- диски и суппорты перекрашиваются с сохранением светотени: преобладающий цвет текстуры (в любом оттенке) становится выбранным цветом, логотипы другого цвета можно оставить; у дисков есть финиш через их `txMaps`;
- стёкла: цвет и затемнение (прозрачность в альфе), по умолчанию только внешние, салонные — по галочке;
- краска CSP: металлик (блёстки), перламутр, хамелеон (два цвета), хром, мат. Пишется `ext_config.ini` скина с шаблонами `common/materials_carpaint.ini` из CSP (`[Material_CarPaint_*]`, `Materials = <материалы краски>`); если у краски маска в альфе текстуры, как у Kunos, добавляется `UseDiffuseAlphaAsMask = 1`. Конфиг базового скина сохраняется, повторный экспорт заменяет только сгенерированную часть. Превью в программе приблизительное;
- перекрашенные детали и конфиг записываются в скин вместе с ливреей.

Баннер на лобовом: если у машины есть отдельная текстура баннера в скине, её можно отметить во вкладке «Основа» и рисовать винилами. Проекция на само стекло отложена: у стёкол обычно маленькие текстуры с общими развёртками.

### Этап 4. Шаблоны

- Привязка свойств к параметрам, панель параметров.
- Галерея шаблонов: встроенные и пользовательские, импорт и экспорт.
- 3–5 встроенных шаблонов.
- Применение шаблона к любой машине с живым превью.

**Статус: готово.** Вкладка ливреи «Шаблон»:

- параметры: стандартные (`number`, `driver`, `team`, `primary`, `secondary`, `accent`, `sponsor1–3` — под колонки таблицы лиги) и свои (текст, цвет, картинка); форма значений;
- текст подставляется через `{id}` прямо в тексте слоя (кнопки-подсказки под полем), цвета слоёв, основы, дисков, суппортов, стёкол и хамелеона CSP — через «Привязку к параметру»; пока цвет привязан, его пипетка меняет значение параметра; картинки-слоты привязываются к параметрам-картинкам и скрываются, пока картинки нет;
- поля `ui_skin.json` понимают `{id}`: у шаблонов по умолчанию `drivername = {driver}`, `number = {number}`, `team = {team}`;
- текст и картинки вписываются в рамку слоя без растяжения (номер «7» и «127» в одном слоте);
- 5 встроенных шаблонов в координатах машины: «Двойные полосы», «Диагональ», «Эндуранс» (слоты трёх спонсоров), «Шевроны», «Минимализм»;
- галерея: наведение показывает шаблон на машине, «Применить» заменяет дизайн (отменяется Ctrl+Z), выбор текстур и базового скина машины сохраняется, введённые значения (номер, пилот…) переходят в новый шаблон;
- свои шаблоны: «Сохранить как шаблон» (файл `.aclivery` с превью в папке данных программы), импорт из файла проекта или шаблона, экспорт в файл, удаление.

### Этап 5. Лига

- Таблица пилотов в UI, импорт CSV / XLSX с сопоставлением колонок.
- Флаги (встроенный набор SVG, `flag-icons`, MIT).
- Пакетная генерация: шаблон × пилоты × машина(ы) → скины в папку игры с `preview.jpg` и `livery.png`.
- Шаблон имени папки скина, например `{number}_{driver}`.
- Прогресс, отмена, отчёт об ошибках.

**Статус: готово.** Вкладка «Лига» (рядом с «Ливреей»):

- таблица пилотов поверх 3D-вида: колонки — параметры шаблона (текст, цвет, флаг, картинка из библиотеки), глаз показывает строку на машине, пустые ячейки берут значения шаблона;
- импорт CSV (разделитель `,` `;` или табуляция, кавычки, BOM) и XLSX (первый лист; свой ридер на `fflate`, без SheetJS с его устаревшей npm-версией); колонки угадываются по заголовкам (RU/EN), сопоставление можно поправить; цвета понимаются как `#rgb`, `#rrggbb`, `rgb()` и названия, страны — как ISO-код, название (EN/RU) или спортивный код (`GER`, `GBR`…), логотипы — по имени наклейки; нераспознанные ячейки перечисляются;
- флаги: `flag-icons` (MIT), 271 флаг, грузятся по требованию; параметр «Страна» ставит флаг в слот и пишет английское название страны в `ui_skin.json`;
- генерация: каждая строка × каждая отмеченная машина → скин в папку игры с `preview.jpg`, `livery.png`, `ui_skin.json`, CSP-конфигом и маркером (в нём дизайн со значениями строки — скин открывается на редактирование); для других машин текстуры и базовый скин выбираются автоматически;
- имена: шаблон папки (`{number}_{driver}` → латиница без пробелов, повторы получают `_2`) и названия в игре (`#{number} {driver}`);
- чужие папки (без маркера AC Livery) не перезаписываются и попадают в отчёт; прогресс, отмена, отчёт об ошибках.

**Библиотека наклеек** (добавлено по просьбе): 16 встроенных вымышленных спонсоров (SVG из кода — настоящие логотипы защищены товарными знаками и не могут входить в открытую программу) и личная библиотека логотипов пользователя (PNG/JPG/WebP/SVG в папке данных программы). Наклейку можно поставить слоем, выбрать для параметра-логотипа шаблона или для ячейки таблицы лиги.

### Этап 6. Релиз

Инсталлятор, автообновление, документация для пользователей (RU/EN), страница релизов.

## 5. Решения по умолчанию (принял сам, можно оспорить)

1. **DDS:** кодируем через `texconv.exe` (DirectXTex, MIT, идёт в комплекте). BC3/DXT5 с мипмапами, если есть альфа, иначе BC1/DXT1. Разрешение как у стоковой текстуры, с опцией 2K / 4K / 8K.
2. **Безопасность записи:** в каждую созданную папку скина кладётся маркер `.aclivery.json`. Скины без маркера программа не перезаписывает без явного подтверждения.
3. **Размеры `preview.jpg` / `livery.png`:** как у стоковых файлов Kunos (сверим на реальных данных).
4. **Нормализация координат** по габаритам кузова, без ручных «якорей» для каждой машины. Твой ответ: только универсальные шаблоны, без гибрида.
5. **Зависимости** только с GPL-совместимыми лицензиями: MIT, BSD, Apache-2.0 (Three.js, opentype.js, SheetJS CE, flag-icons, i18next).
6. **3D без `@react-three/fiber`** (изменено на этапе 1): вьюер и запекатель пишем на чистом Three.js в одном WebGL-контексте, а React только монтирует canvas. Так запечённая текстура сразу показывается на модели без копирования через CPU, а загрузка моделей и камеры проще управляются императивно.
7. **Оси машины** берём по дамми-нодам `WHEEL_LF/RF/LR/RR`. Если модель хранится в зеркальной системе координат, вьюер отражает её для показа, а проекции работают в исходных координатах. Нет колёс — оси по габаритам и предупреждение.
8. **Альфа-канал** ливреи берём из оригинальной текстуры модели: некоторые шейдеры используют её как маску.

## 7. Риски и как с ними жить

| Риск                                                             | Что делаем                                                                                                                                           |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Зашифрованный `.kn5` у модов                                     | Детектируем, помечаем машину «не поддерживается» с объяснением                                                                                       |
| Левый и правый борт делят одну область UV (зеркальная развёртка) | Детектируем перекрытие UV и предупреждаем: несимметричный дизайн (номер на одном борту, текст) на такой машине невозможен                            |
| Кривые UV у модов: растяжки, швы                                 | Отсечение по углу нормали, дилатация, предупреждение о проблемных зонах                                                                              |
| AO из стока «тащит» стоковые логотипы                            | Выбор самого чистого скина, режим «только затемнение», ползунок силы, выключатель                                                                    |
| Очень разные кузова (хэтчбек и прототип)                         | Нормализация по габаритам. Идеального совпадения не обещаем, шаблон можно подвинуть на конкретной машине                                             |
| Формат CSP меняется между версиями                               | Изолируем генерацию `ext_config.ini` в отдельный модуль, сверяемся с документацией CSP                                                               |
| Нет тестовых данных в CI                                         | Модели Kunos нельзя класть в публичный репозиторий. Для тестов генерируем синтетические `.kn5` и используем моды со свободной лицензией, если найдём |
